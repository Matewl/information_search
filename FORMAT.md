# Формат L0INDEX, версия 2

Все целые числа little-endian, без выравнивания и struct padding. Смещения
отсчитываются от начала соответствующего файла. Пустые файлы допустимы для
сегмента без термов. Для открытия нужен готовый `manifest`.

## Манифест

Текст UTF-8, разделители — пробелы и переводы строк:

```text
L0INDEX 2
unicode-casefold-alnum-snowball-english-3.0.1-v2-<Unicode major>.<Unicode minor>
score-desc-stable-v1
128 <documents:u32> <tokens:u64> <segments:u64>
segment-0 <first_doc:u32> <document_count:u32>
segment-1 <first_doc:u32> <document_count:u32>
...
```

Диапазоны документов последовательны и не пересекаются. Первый docID равен 0.
DocID присваиваются после глобальной сортировки по `score` по убыванию. При
равных оценках сохраняется исходный порядок файлов и строк. Поле ранжирования
манифеста фиксирует этот контракт для любого поискового запроса.
Версия 1 несовместима: для стемминга и ранговых docID требуется перестроить индекс.
Число токенов — сумма числа токенов всех документов до какой-либо фильтрации
(стоп-слова не удаляются).

## Документы

`documents.idx`: `documents + 1` значений `u64`. Первые `documents` — начала
записей, последнее — размер `documents.bin`.

`documents.bin`: для каждого документа последовательно:

| Поле | Кодирование |
|---|---|
| Исходный ID | длина `u32`, затем байты UTF-8 |
| URL | длина `u32`, затем байты UTF-8 |
| Путь исходного Parquet | длина `u32`, затем байты UTF-8 |
| Номер строки файла | `u64`, с нуля |
| Исходный score | IEEE 754 binary64, 8 байт little-endian |

`score` должен быть конечным числом. Его точное двоичное представление сохраняется
через `memcpy`, без округления до `int_score`. В последовательности docID значения
score не возрастают, включая границы сегментов.

## Словарь сегмента

`segment-N.keys`: конкатенация нормализованных UTF-8 термов в лексикографическом
порядке. После Unicode case folding для токенов a-z применяется Snowball English
3.0.1; номер позиции исходного токена при этом сохраняется.

`segment-N.terms`: массив записей по 40 байт, индекс записи — termID:

| Смещение | Тип | Значение |
|---:|---|---|
| 0 | `u64` | Смещение ключа в `.keys` |
| 8 | `u32` | Длина ключа в байтах |
| 12 | `u32` | Document frequency в этом сегменте |
| 16 | `u64` | Начало posting list в `.post` |
| 24 | `u64` | Начало skip list в `.skip` |
| 32 | `u32` | Число posting-блоков |
| 36 | `u32` | Резерв, 0 |

`segment-N.trie`: массив узлов Patricia по 16 байт. Корень — узел 0.

| Смещение | Тип | Значение |
|---:|---|---|
| 0 | `u32` | Номер различающего бита, или `0xffffffff` для листа |
| 4 | `u32` | Левый потомок (нулевой бит) |
| 8 | `u32` | Правый потомок (единичный бит) |
| 12 | `u32` | termID для листа |

Неиспользованные поля равны `0xffffffff`. Ключ кодируется девятью битами
на байт: `1` и восемь битов байта от старшего к младшему, затем завершающий `0`.
Номера различающих битов строго возрастают на пути от корня. Ключ в листе
всегда сравнивается целиком, чтобы отклонять отсутствующие термы.

## Posting-блоки

`.post`: конкатенация блоков по термам, внутри терма — по возрастанию docID.
Заголовок каждого блока:

| Смещение | Тип | Значение |
|---:|---|---|
| 0 | `u32` | Число документов `n`, 1…128 |
| 4 | `u32` | Размер сжатого потока docID в байтах |
| 8 | `u32` | Размер сжатого потока term frequency в байтах |
| 12 | `u32` | Размер сжатого потока координат в байтах |

Затем три соответствующих потока PForDelta без дополнительного выравнивания.
Каждый поток состоит из последовательных PForDelta-фреймов по 1…128 целых.

- DocID: `n` значений, первый абсолютный, остальные — положительные разности.
- TF: `n` положительных частот.
- Координаты: `sum(TF)` значений, сгруппированных по документам. Первая координата
  каждого документа абсолютная, последующие — положительные разности. Граница
  документа определяется TF; граница PForDelta-фрейма не сбрасывает delta-базу.

Для обычных булевых запросов достаточно прочитать поток docID. Потоки TF и
координат распаковываются по запросу позиционного оператора.

## PForDelta-фрейм

| Поле | Тип | Значение |
|---|---|---|
| `n` | `u8` | Число целых, 1…128; 128 кодируется как `0x80` |
| `b` | `u8` | Число младших битов на значение, 0…32 |
| `e` | `u8` | Число исключений, 0…128 |
| packed | `ceil(n*b/8)` байт | Младшие `b` бит каждого значения |
| exceptions | переменная длина | `e` пар `(индекс:u8, старшие биты:varint)` |

Bit packing использует младшие биты первого байта первыми. Значение `i` начинается
с бита `i*b`. Неиспользованные старшие биты последнего байта равны нулю.
Исключения упорядочены по индексу, индексы уникальны и меньше `n`.
Старшие биты строго положительны. Восстановление: `low | (high << b)`.
При `b=0` packed-поток пуст, при `b=32` исключений нет.

Varint — unsigned LEB128, 7 бит данных в байте, старший бит означает продолжение,
максимум 5 байт для `u32`. Выбирается ширина `b`, минимизирующая суммарную длину
packed и exceptions; заголовок имеет постоянную длину.

## Skip lists

`.skip`: для каждого терма:

1. `block_count:u32`, `upper_level_count:u32`.
2. Базовый уровень: `block_count` записей по 16 байт:
   `last_doc:u32`, `document_count:u32`, `posting_offset:u64`.
3. Верхние уровни в порядке возрастания stride `8, 64, 512, …`, пока stride
   не превышает число блоков. Заголовок уровня: `stride:u32`, `entry_count:u32`.
   Затем `entry_count = floor(block_count/stride)` записей по 8 байт:
   `last_doc:u32`, `block_index:u32`. Запись `k` адресует блок
   `(k+1)*stride−1` и хранит его максимальный docID.

Связь между уровнями вычисляется по номеру блока и stride; указатели памяти
не сериализуются. Итератор начинает с текущего положения, спускается от самого
разреженного уровня к базовому и пропускает только группы с `last_doc < target`.
